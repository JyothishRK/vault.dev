2 Tier:
---

- 2 Layers:
    - Client
    - Database
- Client server architecture
- Advantage
    - Easy to maintain
- Disadvantage:
    - Scalability
    - Security (Client -> DB Access)

3 Tier:
---

- 3 Layers:
    - Client
    - Business Layer (Application server)
    - Data Layer
- Business Layer acts as interface between user and DB.
- Advantage:
    - Scalable
    - Secure

---

- Domain constraints
    - Attribute based: Name (string), age (int && > 0)...
- Entity Integrity Constraints
    - Primary key (unique and not null)
- Referential Integrity Constraints
    - Foreign key
- Key Constraints
    - Unique attribute -> Candidate key.

Key:
--
- Key is an attribute that can help us uniquely identify a tuple.

Candidate key:
--
- Set of all keys -> Candidate key.

Primary key:
--
- From the set of candidate key - a key will be selected as primary key which satisfies not null and unique.

Super key:
--
- Combination of attributes to uniquely identify tuple.
- Super set of any candidate key -> Super key

    - Complex (Composite + Multi valued)

Degree of Relationship -> Cardinality

    - M -> 1

    - Conceptual Schema - Logical level
    - Physical Schema - Physical(internal) level

- Diagram

- External schema - User specific view what is visible to an user.

- Conceptual schema - E-R Model

- Physical schema - How data is stored. (centralised or distributed)

- Eg: 
    - Studentlogs in and sees his/her marks - External Schema.

- Data Abstraction
- User just needs the data, no need of info of additional details.

- Logical Data Independence:
    - Change in schema wont affect the View (Application) Layer
    - Implemented using Views -> Change in Conceptual schema wont affect the user view.

- Physical Data Independence:
    - Change in Physical schema wont affect Conceptual schema
    - Change storage, structure, index... these wont affect Conceptual schema.
